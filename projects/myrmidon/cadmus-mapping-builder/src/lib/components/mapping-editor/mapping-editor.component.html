Mappings

  • source type: here just item/part.
  • source: the JMES path expression defining input data.
  • SID: usually set in root mappings, and inherited by children unless overridden. The SID identifies the source of mapped data, and must always start with the item or part's GUID (e.g. {$part-id}/{@eid}): when updating an item or a part, all the nodes/triples whose SID starts with its GUID are replaced.
  • filters (root mappings only): in Cadmus, a mapping is applied only to the sources matching all its filters; a filter on a value missing from the source never matches. The test tab runs the mapping anyway, but warns when its filters do not match the test metadata.
    • facet filter: equal to the item's facet ID.
    • group filter: regular expression matching the item's group ID.
    • title filter: regular expression matching the item's title.
    • flags filter: numeric value representing flags bits. The item must have all these flags.
    • part type filter: equal to the part's type ID.
    • part role filter: equal to the part's role ID.
  • description
  • output:
    • nodes: nodes to emit (here key uid [label|tag], one per line). URIs ending with ## are unique: they get a numeric suffix when already used by another source;
    • triples: triples to emit (here S P O or S P "literal", optionally followed by @lang or ^^type, one per line; a stands for rdf:type);
    • metadata: metadata to consume within the mapping context (here key=value, one per line). Presets:
      • item-id: item GUID.
      • item-title: item's title.
      • item-facet: item's facet ID.
      • item-group: item's group ID; for composite IDs (e.g. a/b), also item-group@1, item-group@2, etc.
      • item-eid: item EID (from metadata part).
      • metadata-pid: the ID of the item's metadata part.
      • part-id: part GUID.
      • part-type-id: part's type ID.
      • part-role-id: part's role ID.
      • .: current leaf node in source JSON.
      • index: index of processed element from a source array.
  • children: optional child mappings.

Templates

  • {@...}: JMES expression.
  • {?...}: node key (may be suffixed by :uri (default), :label, :sid, :src_type).
  • {$...}: metadata key.
  • {!...}: macro, with arguments separated by & . Macros:
    • _hdate(json & property): handles a Cadmus historical date and returns either its sort value, or its human-friendly, machine-parsable text value. Arguments: json, the JSON code representing the Cadmus historical date; property, either value or text.
    • _substring(string & index & [length]): substring.
    • cod-loc: codicological location (from Cadmus.Codicology.Mapping).
